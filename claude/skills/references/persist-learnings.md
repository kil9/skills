# 세션 지식을 영속화하는 기준 · 목적지 · 쓰는 법

`/learn`(이번 세션의 학습을 골라 남긴다)과 `/wrap-up`(세션을 닫기 전에 남길 것을 전부 남긴다)이
함께 쓴다. **독자는 미래의 Claude Code 세션이다** — 대화 기록 없이 repo·backlog·메모리만 보고
시작하는 세션.

## 남길 것과 남기지 않을 것

판정 질문은 하나다: **이걸 모르는 새 세션이 무엇을 치르는가.**

- **남긴다** — 여러 번 탐색하거나 **실패를 겪어야** 알게 된 것, 모르면 피해가 큰 것(데이터 손실·
  외부 발송·되돌리기 어려운 작업). 함정, 굳힌 명령, 순서 제약, 크로스 파일 결합, 미설정 시 동작,
  겉보기와 다른 실제 원인, 실측값, **반박된 가설**(다시 시도하지 않게), 사용자가 내린 결정과 근거.
- **남기지 않는다** — 코드·파일을 열면 바로 아는 구조, git 히스토리에 있는 과거 수정, 틀려도 곧바로
  드러나고 싸게 고치는 실수, 이 대화에서만 의미 있는 맥락, 일반적인 코딩 상식.

한두 번 탐색으로 파생되는 것은 남기지 않는다(zip-it 의 keep 기준과 같다). 없는데 억지로 만들지 않는다.

## 목적지

**소유 repo** 는 지금 cwd 가 아니라 그 지식이 다루는 코드·설정이 사는 repo 다. 그 repo 에 backlog 가
없으면 그 repo 의 작업을 등록해 온 backlog 를 쓴다(`git log --grep '\[task-'` 로 확인한다 — 예:
kil9/skills 의 스킬 작업은 kil9conf backlog 에 등록해 왔다).

| 무엇 | 어디에 |
|---|---|
| 진행 중 작업의 상태 · 다음 걸음 · 막힌 이유 | 그 태스크 notes(`backlog task edit N --append-notes`) |
| 반드시 해야 할 후속 | 새 태스크, 한 목표를 이루는 여럿이면 마일스톤 — 형식은 `~/.claude/skills/add-backlog/SKILL.md` |
| 있으면 좋은 개선 · 외부 조건(미출시·응답 대기)에 막힌 후속 | draft |
| 여러 태스크에 걸친 설계 결정 | `backlog decision create` |
| 함정 · 실측 · 운영 지식 | 소유 repo 의 `backlog/docs/`(다루는 doc 이 있으면 `## §N` 절을 덧붙인다), backlog 가 없으면 repo 의 문서 관례. AGENTS.md 에는 검색 경로만 남긴다 |
| 반복 절차 · 워크플로 | 스킬 신설(`/skill-creator`) 또는 기존 SKILL.md 보강 |
| repo 작업 규칙 | repo AGENTS.md |
| 머신 전용 정책 · 사용자 선호 | auto-memory — 오래 변하지 않는 취향·방침만. 버전·날짜·파일명·수치·현재 상태를 품으면 메모리가 아니라 doc 감이다(`/cleanup-memory` 기준) |
| 머신 무관 범용 규칙 | 글로벌 `~/.claude/CLAUDE.md`(실체 `~/kil9conf/claude/CLAUDE.global.md`). 규칙만 짧게 두고 근거·함정은 소유 repo doc 으로 내린다. 길다는 이유로 다른 상시 로드 지침으로 옮기지 않는다 |

- 쓰기 전에 grep 한다. **같은 내용을 담은 파일이 있으면 새로 만들지 않고 그 파일을 고친다.**
- doc·태스크를 새로 만들기 전에 그 repo 를 리모트와 맞춘다. stale 한 체크아웃에서 만들면 그 사이
  리모트에 생긴 doc·태스크와 번호가 겹친다(겹쳤을 때의 처리는 `backlog-basics.md` 의 ID 발급).
- 태스크 description·notes 는 **그것만으로 읽히게** 쓴다 — 발견 맥락·관련 경로·재현 명령을 넣는다.
  새 세션에게는 "아까 그 문제" 가 없다.

## 쓰는 법

- **미래의 나에게 지시하듯** 쓴다. "\~였다"(회고)가 아니라 "\~하라 / \~를 먼저 확인하라"(지침).
  진행 상태를 적는 notes 는 예외로 사실을 쓴다.
- 실패를 겪어야 아는 것은 **증상 → 원인 → 대응** 으로 압축한다. 증상을 빼면 미래 세션이 그 지식을
  꺼내 쓸 트리거를 잃는다 — 에러 문구는 grep 되게 원문 그대로 둔다.
- **검증하지 않은 가설을 규칙으로 굳히지 않는다.** 근거(명령 출력·이슈 번호·파일 라인)를 함께 남기고,
  확인하지 못했으면 "가설" 이라고 표시한다. 이 기록은 세션을 넘어 살기 때문에 틀린 한 줄이 미래의
  모든 세션을 오염시킨다. 그럴듯한 추론일수록 위험하다 — 다음 세션은 그걸 기정사실로 읽는다.
- 상대 날짜("어제", "지난주")는 절대 날짜로 바꾼다.
- 문서·스킬을 고칠 때는 zip-it 기준(정보 단가)을 지킨다.
