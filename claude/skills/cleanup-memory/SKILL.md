# Cleanup Memory — 장기 메모리 감사

**메모리에 남길 것은 오래 변하지 않는 취향·관계·방침·규칙뿐이다.** 함정·실측·조사 결과·"지금
이렇게 돼 있다"는 상태는 그 자산이 사는 repo 의 `backlog/docs/`(없으면 repo 관례의 문서)로 내리고
메모리에서 지운다.

> **`/learn` 과 혼동 금지.** learn 은 이번 세션의 학습을 **추가**한다. 이 스킬은 이미 쌓인 메모리를
> **감사·이관·삭제**한다. 이관한 뒤 남길 문서를 다듬는 것은 `/zip-it` 기준을 따른다.

## 왜 이 작업이 필요한가

메모리는 코드와 함께 갱신되지 않는다. repo doc 은 같은 커밋에서 고쳐지고 grep 되지만, 메모리는
아무도 안 고쳐서 **오래된 '현재값'이 매 세션 답변 정확도를 갉아먹는다.** 2026-08-22 첫 감사에서
20건 중 17건이 함정·조사 로그였고, 저장소 이관(kil9conf → gadgets) 뒤 죽은 경로를 가리키거나
"현재 사용 중인 펌웨어"가 패치 두 개 전 것으로 남아 있었다.

## 절차

### 1. 전수 수집

컨텍스트가 준 memory 경로의 **상위(`projects/`)까지 올라가 모든 프로젝트 슬러그를 훑는다.** 지금
세션의 슬러그만 보면 안 된다 — 관련 지식이 다른 슬러그에 살아 있고, 그래서 정작 그 repo 에서
일할 때 로드되지 않는 배치 오류가 이 감사에서 드러난다.

- 실물은 ccs 프로필 심링크 뒤에 있다. **`find`/`grep -r` 는 심링크를 안 따라간다** — `find -L`,
  `grep -R`, 또는 `readlink -f` 로 실경로를 잡아 쓴다. 이걸 놓치면 "메모리 없음"으로 오판한다.
- 각 슬러그의 `MEMORY.md`(인덱스)와 개별 파일을 모두 읽는다.

**완료 기준**: 모든 슬러그의 메모리 파일 수와 총 바이트를 셌고, 전부 읽었다.

### 2. 사실 대조 — 읽은 것을 믿지 말고 실측한다

메모리 본문이 가리키는 것을 현재 상태와 대조한다. 이 단계가 감사의 값을 만든다.

- **경로**: 적혀 있는 파일·스크립트가 아직 존재하는가. 저장소 이관·리팩터링으로 통째로 죽어 있는
  경우가 많다.
- **현재값**: "현재 사용 중", "조치 현황", 버전·바이너리명·수치. 낡았는지 싸게 검증되면 확인하고,
  비싸면 그 주장을 이관 대상에서 빼거나 "그때 확인하라"로 바꿀 후보로 표시한다.
- **커버리지**: 그 지식을 **이미 담은 doc 이 있는지 repo 에서 grep 한다.** 있으면 이관이 아니라
  그냥 삭제다. 새 doc 을 만들어 중복을 늘리지 말 것.
- **끊긴 위키링크**: `[[name]]` 이 실재하는 메모리를 가리키는지. 슬러그가 다르면 링크는 죽는다.

**완료 기준**: 메모리 한 건마다 (경로 유효성 / 커버 하는 doc / 낡은 현재값) 세 항목의 판정이 있다.

### 3. 분류하고 승인받는다

네 갈래로 가르고, **실행 전에 사용자에게 제시한다**(이 게이트는 건너뛰지 않는다 — 삭제가 섞여 있다).

| 갈래 | 처리 |
|---|---|
| 영구 정책·취향·작업 규칙 | 메모리에 유지 |
| 과거엔 맞지만 지금은 낡음 | 낡은 부분을 도려내고 이관 또는 삭제 |
| 살릴 가치가 있는 함정·실측 | repo doc 으로 이관 후 메모리에서 삭제 |
| 이미 doc 이 커버 / 그때 찾으면 되는 값 | 그냥 삭제 |

판별이 헷갈리면: **버전·날짜·파일명·수치·현재 상태를 품고 있으면 메모리가 아니라 doc 감이다.**

**완료 기준**: 사용자가 실행 범위를 승인했다.

### 4. 백업

지우기 전에 메모리 디렉터리 전체를 scratchpad 에 복사하고 파일 수를 보고한다. 되돌릴 수 있어야
과감하게 정리할 수 있다.

**완료 기준**: 백업 경로와 파일 수를 사용자에게 알렸다.

### 5. 이관

대상 repo 의 체크아웃을 **먼저 동기화한다.** stale 한 곳에 새 doc 을 만들면 그 사이 원격에 생긴
doc 과 **ID 가 충돌한다**(실제로 38커밋 stale 이라 doc-29·30 을 모르고 31을 쓸 뻔했다).
`git rev-list --left-right --count` 로 확인하고, 파괴적 작업 전에는 `git cherry` 로 고유 커밋을 본다.

- 다루는 doc 이 이미 있으면 새로 만들지 말고 `## §N` 절을 덧붙인다. doc 끼리 `§N` 으로 서로 참조한다.
- **이관하면서 낡은 것을 버린다.** 경로는 현행으로 교정하고, **빌드마다 바뀌는 값(현재 펌웨어명,
  BIOS 버전, 조치 진행 상황)은 아예 적지 않고 "그때 확인하라"로 대체한다.** 그대로 옮기면 메모리에서
  썩던 것이 doc 에서 썩을 뿐이다.
- 조사 로그는 결론으로 압축한다 — 시각별 서사·"관찰 중"·"다음 카드"는 값이 없다. 값은 지문·판별법·
  반박된 가설이다.
- doc 번호는 생성 후에야 확정되므로, **본문에 쓴 상호참조 번호를 마지막에 교정한다.**
- repo 의 AGENTS.md 에 doc 색인이 있으면 함께 갱신한다.

**완료 기준**: 새 doc 이 CLI/목록에 인식되고, 이관한 지식이 새 위치에 실제로 있으며(grep), 죽은
경로가 남아 있지 않다.

### 6. 메모리 재구성

- 삭제 대상을 지운다.
- 남은 것은 정책만 담도록 다시 쓴다. 근거는 **관측된 실패 한 줄**로 줄이고 상세는 doc 에 맡긴다.
- 각 슬러그의 `MEMORY.md` 를 다시 쓴다. 첫 줄에 **"여기에는 정책만 둔다, 함정은 <repo>/backlog/docs
  에 있다"** 를 박아 재발을 막는다. 남은 게 없는 슬러그의 인덱스는 지운다.
- 배치가 어긋나 있었으면(그 repo 에서 일하는데 메모리가 다른 슬러그에 있었으면) 옮긴다. 여러
  프로젝트에서 필요한 정책은 슬러그마다 사본을 둔다 — 메모리는 프로젝트별로만 로드된다.

**완료 기준**: 남은 메모리 전부가 정책이고, 전후 파일 수·바이트를 보고했다.

### 7. 커밋

이관으로 생긴 repo 변경을 `/commit` 규칙대로 커밋한다. 메모리 디렉터리는 git 이 아니므로 커밋
대상이 아니다. 여러 repo 를 건드렸으면 repo 마다 따로 커밋한다.
