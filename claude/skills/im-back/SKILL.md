# I'm back — 이 세션이 무엇을 했는가

돌아온 사람은 **자기가 없는 동안 무엇이 벌어졌는지** 모른다. 그가 알아야 하는 것은 순서대로 셋이다:
무엇이 끝났나 · 무엇이 바깥으로 나갔나 · 무엇이 자기 판단을 기다리나.

**기억으로 쓰지 않는다.** 대화는 요약되고 요약은 조용히 빠뜨린다. 커밋했다고 기억하는 것이 실제로는
커밋되지 않은 채 남아 있는 일이 실제로 일어난다(명령이 중간에 죽는 경우). 그래서 이 스킬의 규율은
**대조**다 — 기억을 git·backlog 로 확인하고, 어긋나면 어긋난 사실을 보고에 적는다.

## 0. 먼저 볼 것 — 계약이 있으면 그것이 최우선 소스

세션 scratchpad(없으면 OS 임시 디렉터리)에 `afk-contract.md` 가 있으면 **그것부터 읽는다.**
`/afk` 가 부재 중 내린 결정·보류한 것·레드라인 로그를 append 해 둔 파일이고, 대화 요약이 지운
것까지 남아 있다. 그 내용을 아래 보고에 녹이고 **계약을 해제한다**(afk §2 의 해제를 이 스킬이
대신 수행한 것이다 — 브리핑을 두 벌 내지 않는다).

없으면 그냥 넘어간다. 계약 없이 도는 것이 이 스킬의 기본값이다.

## 1. 범위를 정하고 밝힌다

"이번 세션" 의 시작점을 다음 중 **가장 이른 것**으로 잡는다:

- 이 대화의 시작(요약돼 시작을 모르면 남은 컨텍스트의 첫 지점)
- 사용자가 자리를 뜬 시점(계약 파일의 발효 시각)
- 내가 만든 첫 커밋의 시각

인자가 있으면 그것이 우선한다(`/im-back 2시간` · `/im-back 배포한 것만`).

**보고 머리에 범위를 한 줄로 밝힌다** — "2026-08-17 21:00 이후 · 이 대화에서 한 것" 처럼. 범위를
밝히지 않은 보고는 사용자가 자기 기억과 맞춰 볼 기준이 없다.

## 2. 3중 대조로 사실을 모은다

세 소스를 **전부** 본다. 하나라도 빠지면 보고가 틀린다.

```bash
git log --format='%h %ad %s' --date=format:'%m-%d %H:%M' <범위>   # 무엇이 커밋됐나
git status --porcelain                                            # 미커밋으로 남은 것
git log origin/<브랜치>..HEAD --oneline                           # push 안 된 것
```

- **git** — 커밋·미커밋·미push. 여러 저장소를 만졌으면 각각 본다(옆 저장소·worktree 포함).
- **backlog**(있으면) — `bash ~/.claude/skills/references/backlog-context.sh` 한 번. 어느 태스크가
  Done 이 됐고 무엇이 새로 생겼고 무엇이 Blocked 인지. 커밋 태그(`[task-N]`)와 태스크 상태가 어긋나면
  그 자체가 보고 항목이다.
- **대화** — 커밋으로 남지 않은 것(조사 결과, 실측 수치, 배포·발송처럼 저장소 밖으로 나간 행위,
  내린 판단과 그 근거). git 만 보면 이것이 통째로 빠진다.

**대조에서 어긋난 것은 숨기지 않는다.** "했다고 기억하지만 커밋이 없다", "태스크는 Done 인데
파일 변경이 없다" 는 그 자체가 사용자가 가장 먼저 알아야 할 사실이다.

**산출물을 다시 만들지 않는다.** 빌드·배포·테스트를 확인하려고 재실행하지 말 것 — 보고하려다
상태를 바꾼다. 이미 남은 로그·릴리스 id·명령 출력을 인용한다.

## 3. 내 것과 남의 것을 가른다

같은 워킹트리에 다른 세션이 붙어 있을 수 있다. 표에는 **이 세션이 한 것만** 넣는다. 판별은
커밋 메시지·태스크 태그·시각을 이 대화의 기록과 맞춰 본다.

그 사이 다른 세션이 만든 변화(낯선 커밋, 새로 생긴 태스크, 옆 저장소의 진행)는 **표 밖에 한 줄로**
분리해 알린다 — "그동안 다른 세션이 X 를 했다". 남의 성과를 내 표에 넣으면 보고가 거짓이 되고,
아예 빼면 사용자가 트리 상태를 오해한다.

## 4. 보고 — 표로 낸다

대화에만 낸다(파일·Artifact 로 만들지 않는다. 진실원본은 git·backlog 이고 보고서 사본은 곧 낡는다).
사용자가 명시적으로 파일이나 공유 페이지를 원하면 그때 만든다.

**상한을 두지 않는다. 전수를 내되 각 줄을 짧게 압축한다** — 빠진 항목이 있으면 보고가 거짓이 되고,
사용자는 그것을 알 방법이 없다. 항목이 많으면 줄을 줄이지 말고 한 줄의 글자를 줄인다.

순서는 이렇게 한다. 해당 없는 절은 통째로 뺀다(빈 표를 내지 않는다).

1. **완료한 것** — 표: `무엇 | 어디에(태스크·마일스톤·저장소) | 한 줄 | 커밋`
2. **바깥으로 나간 것** — 표: push·배포·게시·발송·외부 API 쓰기처럼 **되돌리기 어렵거나 남이 보는**
   행위. 릴리스 id·URL·대상을 적는다. 없으면 "바깥으로 나간 것 없음" 한 줄로 명시한다 — 없다는
   사실 자체가 사용자가 확인하고 싶은 것이다.
3. **실측으로 확정한 사실** — 표: `항목 | 실측 결과`. 조사·디버깅에서 참으로 굳힌 것. 커밋 메시지에
   흩어져 재사용되지 못하는 값이 여기 모인다(숫자·원인·경계 조건).
4. **미해결 · 확인이 필요한 것** — 사용자 판단이 필요한 갈림길, 봐야 할 diff, 뜻밖의 발견, 막힌 것과
   막힌 이유. **보고의 값은 대개 여기 있다.**
5. **다음 액션 추천** — 하나만, 근거와 함께. backlog 가 있으면 ready set 기준으로 고른다.

마지막에 **다른 세션 한 줄**(§3)과 **미커밋·미push 잔여물**을 붙인다.

## 5. 보고하고 멈춘다

**착수하지 않는다.** 다음 액션은 추천으로 적기만 하고, 사용자의 지시를 기다린다 — 돌아온 사람이
무엇을 할지 고르는 자리다. 확인 질문(`AskUserQuestion`)도 보고 뒤에 붙이지 않는다.

예외는 하나다: 보고 도중 **지금 손대지 않으면 손실이 커지는 것**을 발견했을 때(폭주 중인 백그라운드
프로세스, 잘못 나간 배포). 그것은 보고 맨 위에 올리고 무엇을 할지 묻는다.
