# Wrap — 세션을 닫기 전에 남길 것을 남긴다

세션을 닫으면 대화·scratchpad·머릿속 판단이 함께 사라진다. 다음 세션은 repo·backlog·메모리만 보고
시작한다. 목적은 하나다: **다음 세션이 그것만 보고 이어가게** 하는 것, 특히 이번 세션이 겪은
트러블슈팅을 다시 겪지 않게 하는 것.

**독자는 미래의 Claude Code 세션이다. 사용자가 아니다.** 결과물은 사람이 읽는 글이 아니라 에이전트가
읽는 기록·지침이고, 아무것도 게시하지 않는다. 사용자가 읽을 산문을 쓰고 있다면 스킬을 잘못 고른
것이다(`/publish-til`). 이미 쌓인 메모리를 감사·정리하는 것은 `/cleanup-memory` 다.

인자가 있으면 우선 남길 것으로 읽는다. 인자가 학습 하나를 가리키면(세션 중간에 "이것만 남겨둬")
§1 의 수집을 그 범위로 좁히고 나머지 절차는 그대로 밟는다.

## 1. 닫으면 사라질 것을 모은다

기억이 아니라 **대조**로 모은다. 대화는 요약되면서 조용히 빠뜨린다. 범위는 이 대화의 시작부터다
(요약됐으면 남은 컨텍스트의 첫 지점과 이 세션의 첫 커밋 중 이른 쪽).

- **대화** — 트러블슈팅에서 겪은 실패와 진짜 원인, 반박된 가설, 실측값, 사용자가 내린 결정과 그 근거.
  커밋 메시지에 없는 것이 대부분 여기 있다.
- **만진 repo 마다** `git status --porcelain` 와 `git log @{u}.. --oneline`. 미커밋 변경은 의도가
  대화에만 있고, 미push 커밋은 다른 머신의 세션이 보지 못한다. worktree·옆 repo 도 본다.
- **backlog**(있으면) — `bash ~/.claude/skills/references/backlog-context.sh`. 이번에 손댄 태스크의
  상태·notes 가 실제 진행과 맞는지 본다.
- **scratchpad** — 세션 전용이라 다음 세션은 경로조차 모른다. 거기 둔 측정 결과·스크립트·초안 중
  남길 가치가 있는 것은 값을 기록으로 옮기거나 repo 로 옮긴다.
- **띄워 둔 것** — background 프로세스, pane 워커, 예약 작업(cron·wakeup), 열어 둔 서버. 세션이 닫히면
  죽거나 고아가 된다. 계속 돌아야 하면 무엇이 왜 돌고 어떻게 멈추는지 기록하고, 아니면 정리한다.

다른 세션이 만든 변화(낯선 커밋, 내가 만들지 않은 태스크)는 기록 대상이 아니다. 커밋 메시지·태그·
시각을 이 대화와 맞춰 가른다.

## 2. 고른다

판정 질문은 하나다: **이걸 모르는 새 세션이 무엇을 치르는가.**

- **남긴다** — 여러 번 탐색하거나 **실패를 겪어야** 알게 된 것, 모르면 같은 실패를 재현하거나 이미 버린
  방향으로 다시 가는 것, 모르면 피해가 큰 것(데이터 손실·외부 발송·되돌리기 어려운 작업). 함정, 굳힌
  명령, 순서 제약, 크로스 파일 결합, 미설정 시 동작, 겉보기와 다른 실제 원인, 실측값, **반박된 가설**,
  사용자 결정과 근거, 진행 중 작업의 상태.
- **남기지 않는다** — 코드·파일을 열면 바로 아는 구조, git 히스토리에 있는 과거 수정, 틀려도 곧바로
  에러로 드러나 금방 고치는 실수, 이 대화에서만 의미 있는 맥락, 일반적인 코딩 상식. 한두 번 탐색으로
  파생되는 것도 남기지 않는다(zip-it 의 keep 기준과 같다).

남길 것이 없으면 그렇게 보고하고 끝낸다. 없는데 억지로 만들지 않는다.

## 3. 목적지를 정해 쓴다 — backlog 가 있으면 backlog 가 기본이다

**소유 repo** 는 지금 cwd 가 아니라 그 지식이 다루는 코드·설정이 사는 repo 다. 그 repo 에 backlog 가
없으면 그 repo 의 작업을 등록해 온 backlog 를 쓴다(`git log --grep '\[task-'` 로 확인한다 — 예:
kil9/skills 의 스킬 작업은 kil9conf backlog 에 등록해 왔다).

| 무엇 | 어디에 |
|---|---|
| 진행 중 작업의 상태 · 다음 걸음 · 막힌 이유 | 그 태스크 notes(`backlog task edit N --append-notes`) |
| 반드시 해야 할 후속 | 새 태스크, 한 목표를 이루는 여럿이면 마일스톤 — 형식은 `~/.claude/skills/add-backlog/SKILL.md` |
| 있으면 좋은 개선 · 외부 조건(미출시·응답 대기)에 막힌 후속 | draft |
| 여러 태스크에 걸친 설계 결정 | `backlog decision create` |
| 함정 · 실측 · 운영 지식 | 소유 repo 의 `backlog/docs/`(다루는 doc 이 있으면 `## §N` 절을 덧붙인다), backlog 가 없으면 repo 의 문서 관례. AGENTS.md 에는 검색 경로만 남긴다 |
| 반복 절차 · 워크플로 | 스킬 신설(`/skill-creator`) 또는 기존 SKILL.md 보강 |
| repo 작업 규칙 | repo AGENTS.md |
| 머신 전용 정책 · 사용자 선호 | auto-memory — 오래 변하지 않는 취향·방침만. 버전·날짜·파일명·수치·현재 상태를 품으면 메모리가 아니라 doc 감이다(`/cleanup-memory` 기준) |
| 머신 무관 범용 규칙 | 글로벌 `~/.claude/CLAUDE.md`(실체 `~/kil9conf/claude/CLAUDE.global.md`). 규칙만 짧게 두고 근거·함정은 소유 repo doc 으로 내린다. 길다는 이유로 다른 상시 로드 지침으로 옮기지 않는다 |

- **진행 중이던 태스크** — notes 에 어디까지 했는지, 다음 걸음(실행할 명령·경로), 막힌 것, 이상할 때 볼
  곳을 적는다. 새 세션이 그 태스크 하나만 열어도 이어갈 수 있어야 한다. 상태도 실제와 맞춘다 — AC 를
  실제로 확인한 항목만 체크하고, 다 확인되지 않았으면 Done 으로 바꾸지 않는다.
- **태스크 description·notes 는 그것만으로 읽히게** 쓴다 — 발견 맥락·관련 경로·재현 명령을 넣는다.
  새 세션에게는 "아까 그 문제" 가 없다.
- **이 세션이 만든 미커밋 변경** — 끝난 것이면 그 repo 커밋 규칙대로 커밋한다. 덜 된 것이면 그대로 두고
  무엇이 덜 됐는지를 태스크 notes 에 적는다. 내가 만들지 않은 변경은 건드리지 않는다.
- 쓰기 전에 grep 한다. **같은 내용을 담은 파일이 있으면 새로 만들지 않고 그 파일을 고친다.**
- doc·태스크를 새로 만들기 전에 그 repo 를 리모트와 맞춘다. stale 한 체크아웃에서 만들면 그 사이
  리모트에 생긴 doc·태스크와 번호가 겹친다(겹쳤을 때의 처리는
  `~/.claude/skills/references/backlog-basics.md` 의 ID 발급).

묻지 않고 기록하는 것이 기본이다. **상시 로드되는 지침(글로벌 CLAUDE.md, repo 의 AGENTS.md·CLAUDE.md
규칙 줄)을 새로 늘리거나 바꿀 것이 있으면** 그것만 모아 AskUserQuestion 으로 한 번에 묻는다 — 모든
세션에 실리는 줄이라서다. 사용자 판단이 필요한 갈림길은 묻지 않고 태스크에 "결정 필요: <질문>" 으로
남긴다.

## 4. 쓰는 법

- **미래의 나에게 지시하듯** 쓴다. "\~였다"(회고)가 아니라 "\~하라 / \~를 먼저 확인하라"(지침).
  진행 상태를 적는 notes 는 예외로 사실을 쓴다.
- 실패를 겪어야 아는 것은 **증상 → 원인 → 대응** 으로 압축한다. 증상을 빼면 미래 세션이 그 지식을
  꺼내 쓸 트리거를 잃는다 — 에러 문구는 grep 되게 원문 그대로 둔다.
- **검증하지 않은 가설을 규칙으로 굳히지 않는다.** 근거(명령 출력·이슈 번호·파일 라인)를 함께 남기고,
  확인하지 못했으면 "가설" 이라고 표시한다. 이 기록은 세션을 넘어 살기 때문에 틀린 한 줄이 미래의
  모든 세션을 오염시킨다. 그럴듯한 추론일수록 위험하다 — 다음 세션은 그걸 기정사실로 읽는다.
- 상대 날짜("어제", "지난주")는 절대 날짜로 바꾼다.
- 문서·스킬을 고칠 때는 zip-it 기준(정보 단가)을 지킨다.

## 5. 커밋한다

기록은 커밋돼야 다른 worktree·머신의 세션이 본다.

- repo 마다 **이번에 만들거나 고친 파일만** 경로로 add 하고(`git add -A`·`commit -a` 금지), 커밋 직전
  `git status --porcelain` 으로 낯선 변경이 섞였는지 본다. backlog 가 gitignore 대상이면 커밋하지 않고
  그 사실만 보고한다.
- 태스크를 고친 커밋에는 `[task-N]` 을 넣는다.
- push 는 이 세션이 그 repo 에 이미 push 해 왔으면 같은 방식으로 한다. 아니면 하지 않고 미push 로
  보고한다 — 세션을 닫으면 아무도 push 하지 않으므로, 다른 머신에서 이어갈 사용자가 알아야 한다.

## 6. 보고한다

짧게 낸다.

1. **남긴 것** — 무엇을 어디에(파일·태스크 ID·doc ID), 커밋 해시.
2. **일부러 남기지 않은 것** — 사용자가 남길 줄 알았을 법한 것만 한 줄씩, 이유와 함께.
3. **남아 있는 것** — 미커밋·미push, 계속 도는 프로세스, "결정 필요" 로 남긴 갈림길.
4. **닫아도 되는가** — "닫아도 된다" 또는 "X 를 먼저" 한 줄.
