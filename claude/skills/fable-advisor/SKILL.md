# Fable Advisor

사용자가 메시지에 `/fable-advisor` 를 붙이면, **Fable 5 모델을 자문역(advisor)으로** 불러 이번 요청에
관점을 하나 더 얹는다. Fable 5 는 Agent 도구를 `model: "fable"` 로 띄운 서브에이전트다.

**자동 호출 금지.** 이 스킬은 사용자가 `/fable-advisor` 를 직접 적었을 때만 동작한다. 계획·설계·중대한
결정이라는 이유만으로 스스로 붙이지 않는다.

## 종량제 게이트 (스킬 진입 시 1회)

Fable 은 비싸다. **구독 한도 안에서 도는 동안만 쓰고, 종량 과금으로 넘어간 상태면 먼저 묻는다.**
스킬에 진입하면 §0 보다 먼저 아래를 확인한다. **이번 세션에서 이미 한 번 물었으면 다시 묻지 않고**
그때 사용자가 고른 선택을 그대로 따른다(대화 기록에 그 문답이 있는지로 판단한다).

두 신호 중 **하나라도** 걸리면 종량제로 본다:

1. **인증·과금 방식** — 구독 OAuth 가 아니라 API 키/클라우드 과금으로 도는 경우.
   ```bash
   env | grep -E '^(ANTHROPIC_API_KEY|ANTHROPIC_AUTH_TOKEN|ANTHROPIC_BASE_URL|CLAUDE_CODE_USE_BEDROCK|CLAUDE_CODE_USE_VERTEX)=' | sed 's/=.*/=<set>/'
   python3 -c "import json,os;p=os.path.join(os.environ.get('CLAUDE_CONFIG_DIR',os.path.expanduser('~/.claude')),'.claude.json');print(json.load(open(p)).get('oauthAccount',{}).get('billingType'))" 2>/dev/null
   ```
   위 환경변수가 하나라도 설정돼 있거나, `billingType` 이 `stripe_subscription` 계열이 아니면 종량제다.
2. **구독 한도 소진** — 한도를 다 쓰면 extra usage 로 넘어가 그때부터 종량 과금이다.
   `~/kil9conf/script/cc-usage-brief.py` 가 있으면 실행해 활성 프로필(`🟢`)의 5h/7d 사용률을 읽고,
   **둘 중 하나라도 95% 이상**이면 종량제로 본다. 그 스크립트가 없는 머신이면 이 신호는 건너뛴다
   (없다고 해서 경고하지 않는다 — 조용히 통과).

둘 다 아니면 아무 말 없이 §0 으로 넘어간다. **경고는 종량제일 때만 낸다.**

걸렸으면 AskUserQuestion 으로 한 번 묻고 **답을 기다린 뒤** 진행한다. 무엇이 걸렸는지(API 키 과금인지,
한도 소진인지)와 현재 사용률을 질문에 담는다. 선택지는 셋:

- **그래도 Fable 로 진행** — 종량 과금을 감수한다.
- **Opus 5 로 대신** — §2 의 강등 경로로 진행하고, 강등 사실을 결과 보고에 밝힌다.
- **자문 취소** — 자문 없이 내가 직접 답한다.

경고 없이 종량제로 Fable 을 띄우지 말 것. 사용자는 한도가 남아 있을 때만 Fable 을 쓰려 한다.

## 0. 무엇을 자문할지 확정

`/fable-advisor` 는 보통 요청 끝에 붙는다. **자문 대상**을 먼저 정한다:

- 메시지에 다른 내용이 같이 있으면 → 그 요청.
- 메시지가 `/fable-advisor` 뿐이면 → 직전 대화에서 다룬 가장 실질적인 것(내가 방금 낸 계획·답안,
  또는 사용자가 마지막으로 물은 것).
- `/fable-advisor` 뒤에 텍스트가 붙어 있으면 그건 자문 초점 힌트로 쓴다(예: `/fable-advisor 성능 관점으로`).

## 1. 모드 선택 (상황에 맞춰 판단)

세 모드 중 상황에 맞는 것을 고른다. 애매하면 **검토**가 기본이다.

- **검토·비평 (기본)** — 내가 먼저 구체적인 답/계획/초안을 만든 다음, 그걸 Fable 5 에 넘겨 허점·리스크·
  놓친 대안을 지적받고 반영한다. 손에 잡히는 산출물이 있을 때.
- **선조언** — 아직 착수 전이고 방향 자체가 불확실할 때. Fable 5 에게 먼저 관점을 물어 그 조언을 반영해
  진행한다. 다 만든 뒤 뒤집는 낭비를 피한다.
- **양자 병기** — 정답이 갈리는 판단·의견 문제라, 두 독립 관점을 합치지 않고 나란히 보여주는 편이
  사용자에게 더 유용할 때. 내 답과 Fable 5 의 답을 각각 라벨 붙여 제시한다.

무거운 구현 작업이면 전부 만든 뒤 검토받기보다 **계획 단계에서 선조언/검토**를 받아 되돌림 비용을 줄인다.

## 2. 티어 선택 — Fable 에 남길 것 / Opus 5 로 내릴 것

**기본은 Fable 이다.** 사용자가 `/fable-advisor` 를 직접 친 이상 그 티어로 도는 것이 기본값이고,
이 절은 "스스로 내려도 된다"가 아니라 **"이런 경우엔 Opus 5 로 충분하다"고 밝히고 그렇게 할 수 있는
재량**이다. 애매하면 Fable 로 둔다.

기준 한 줄: **내가 답을 갖고 있고 확인만 필요하면 Opus 5, 답 자체를 모르면 Fable.**

- **Fable 유지** — 방향 자체가 불확실한 선조언, 정답이 갈리는 판단(양자 병기), 긴 글의 문장·구성,
  수 시간짜리 자율 실행 설계.
- **Opus 5 로 내림** — 정형화된 체크리스트 검토, 이미 답이 있고 사실오류만 훑는 확인, 기계적인 반복 리뷰.
  Opus 5 가 절반 값에 Fable 5 를 앞선 벤치가 근거다.

**조용한 강등 금지.** 내려서 돌면 사용자에게 한 줄로 밝힌다
(예: "체크리스트 검토라 Opus 5 로 자문했습니다"). 밝히지 않고 내리면 사용자는 Fable 관점을 받았다고
오해한 채 결정한다.

## 3. 자문 스폰

서브에이전트는 내 대화를 **상속하지 않는다.** 프롬프트에 자문에 필요한 맥락을 스스로 담아라:

- 원래 요청(사용자의 목표·제약).
- 검토 모드면 내 초안/계획 전문.
- 관련 파일 경로(서브에이전트가 직접 읽도록) — 코드 전문을 붙여넣기보다 경로를 주는 편이 낫다.
- **무엇을 원하는지 명시**한다: "이 계획의 허점과 놓친 대안을 지적하라", "이 답의 사실오류·리스크를
  짚어라" 등. 막연히 "검토해줘"라고 던지지 말 것 — 그러면 맹탕 자문이 돌아온다.

스폰 규칙:

- `model: "fable"`(§2 에서 내렸으면 `model: "opus"`).
- **`name` 파라미터를 주지 말 것.** 에이전트 팀 기능이 켜져 있으면 `name` 이 있는 스폰은 서브에이전트가
  아니라 팀원이 되고, **팀원의 최종 보고는 호출자에게 전달되지 않는다**(`SendMessage(to: "main")` 으로만
  회신한다). 스폰은 성공하고 자문역도 멀쩡히 일하며 idle 통지까지 오기 때문에, 이 유실은 "자문이
  맹탕이었다" 로 오해되기 딱 좋다 — 실제로 완성된 보고 두 건이 그렇게 사라졌다. 자문역을 부르는 이름이
  필요하면 `description` 에 넣는다(그쪽은 UI 에 그대로 뜨고 스폰 종류를 바꾸지 않는다). 이름 짓는 규칙이
  따로 있으면 그 규칙을 `description` 에 적용한다.
- 기본은 **서브에이전트 하나.** 여러 렌즈(보안/성능/사용성 등)가 정말 필요할 때만 병렬로 늘리되
  **최대 3개까지다** — 자문 하나에 Fable 을 무더기로 띄우지 않는다. 렌즈가 더 떠오르면 늘리지 말고
  가장 값나가는 셋으로 추린다. 사용자가 개수를 명시하면 그 지시가 이 상한보다 우선한다.
- 서브에이전트의 최종 보고는 사용자에게 보이지 않는다. 받은 자문을 내가 요약·전달해야 한다.

## 4. 반영과 전달

- 자문을 **무비판 수용하지 말 것.** 동의/이견을 내 판단으로 가려 반영한다.
- 무엇을 자문받아 무엇이 바뀌었는지 사용자에게 짧게 밝힌다
  (예: "Fable 자문: …. 그중 …를 반영, …는 이견이라 유지").
- 양자 병기 모드면 두 관점을 라벨을 붙여 나란히 제시한다.
- 대상이 정말 사소하면 자문으로 무겁게 만들지 말고, 한 줄로 "자문 불필요"를 밝히고 넘어가도 된다.
