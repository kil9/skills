방금 만든 산출물을 사용자가 경로를 복사해 여는 왕복 없이 옆 pane 의 vi 로 바로 보여준다.
읽기용 뷰어다 — 열어 주고 끝이며, 평소에는 닫는 것은 사용자다(편집 승인 플로우가 아니다). 단 그 문서의 쓰임이
끝났으면 에이전트가 닫는다(아래 '쓰임이 끝나면 닫는다').

## 절차

1. **herdr 확인.** `HERDR_ENV` 가 `1` 이 아니면 pane 을 열 수 없다 — 파일 경로 목록만 보고하고 끝낸다.

2. **대상 선정.** 인자 경로가 있으면 그대로. 없으면 이 세션에서 방금 만들었거나 실질적으로 고친
   **문서**(md·텍스트·초안·리포트)를 최근 것부터 고른다. 코드 파일은 사용자가 명시했을 때만.
   대화에서 특정이 안 되면 추측으로 열지 말고 후보를 대며 묻는다(AskUserQuestion).

3. **만들어서 띄우라는 요청일 때만 다듬는다.** "만들어서 옆에 띄워줘" 처럼 문서 생성과 띄우기를 함께
   받았으면, 생성하는 단계에서 한국어 글을 `korean-polish` §7(게시 전 퇴고)로 거른 뒤 연다. 단계(L0-L2)는
   본문 길이로 정해진다. 이미 만들어 둔 문서를 띄우기만 하라는 요청이면 다시 점검하지 않는다. 생성 때
   이미 거쳤거나 사용자가 본 글이라 이중 점검이 된다. 코드·로그·설정 파일은 어느 쪽이든 건드리지 않는다.

4. **pane 하나에 vi 하나가 기본.** 파일이 여러 개여도 한 vi 에 모두 넘긴다: 2개는 `vi -o`(오른쪽
   pane 은 세로로 길어 `-O` 보다 낫다), 3개 이상은 `vi -p` 탭. pane 을 여러 개 여는 것은 사용자가
   "나란히 비교"를 명시했을 때만, 그때도 2개까지 — pane 이 늘수록 좁아져 문서가 안 읽힌다.

5. **스폰.** [`../references/vi-pane.md`](../references/vi-pane.md) 의 보기용(`; exit` 를 붙여 `:q` 로
   pane 이 닫히게)으로 연다. 포커스·앵커·절대경로 규칙도 그 문서를 따른다.

6. **보고.** 무엇을 어떤 배치(분할/탭)로 열었는지 한 줄로 알리고 끝낸다. 탭이면 `gt` 로 넘긴다고
   덧붙인다. pane 을 기다리지 않는다.

7. **쓰임이 끝나면 닫는다.** 띄운 문서가 게시 초안(코멘트·이슈·메일 등)이었고 게시를 마쳤으면, 게시 직후 그 pane 을
   닫는다(`herdr pane close <pane_id>`) — 게시했다는 것은 사용자가 검토·편집을 끝냈다는 뜻이다. 게시를 취소했거나
   대화 흐름상 그 문서가 더 필요 없다고 판단될 때도 닫는다. 이미 닫혀 있으면(`pane_not_found`) 그대로 둔다.
   그래서 스폰할 때 받은 pane id 를 기억해 둔다(2026-10-28 사용자 지시).

## 유의

- **문서가 원격 이미지 URL(이미지 저장소의 raw 주소 등)을 가리키면, 띄우기 전에 그 이미지를 먼저
  올린다.** vi 로는 그림이 안 보여 사용자가 브라우저로 URL 을 열어 봐야 하는데, 올리지 않은 URL 은
  404 다. 쓰지 않게 되면 그때 지운다(2026-10-27 사용자 지시). 보고에 이미지 URL 을 함께 적는다.

- 편집을 요청하고 결과를 회수하는 초안 플로우(kil9-writing-style·scopic-pr 류)도 같은 레시피의
  편집용을 쓴다 — 회수 전에 pane 이 사라지면 안 되므로 `; exit` 없이 열고, 승인 후 에이전트가 닫는다.
