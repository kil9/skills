---

사안 하나를 놓고 **비판 → 옹호 → 종합** 세 서브에이전트가 한 회차를 이루고, 이를 지정한 횟수만큼
반복한다. 리더(나)는 진행만 맡는다. 사안에 대한 내 의견을 서브에이전트에게 얹지 않고, 결론도 마지막
종합 에이전트의 것을 그대로 전달한다.

인자: 사안(필수), 반복 횟수 n(선택, 기본 1). `3번`·`3회`·`n=3`·`x3` 처럼 오면 n 으로 읽는다.

## 0. 사안 확정

- **사안**은 인자에서 횟수 표현을 뺀 나머지다. 비었으면 직전 대화에서 가장 실질적인 것(내가 방금 낸
  계획·답안, 사용자가 마지막으로 다룬 결정)을 쓴다. 그래도 모호하면 한 번만 묻는다.
- 사안이 파일·디렉터리·PR·diff·URL 을 가리키면 **경로를 그대로 넘기고** 서브에이전트가 직접 읽게 한다.
  내가 요약해 넘기면 내 해석이 섞인다. 대화에만 있는 맥락(제약, 사용자가 밝힌 목표)은 사실만 적어 붙인다.
- 이 묶음을 **사안 브리프**라 부르고, 모든 회차·모든 역할에 똑같이 넘긴다.

## 1. 역할

모두 Agent 도구로 띄운다. `name` 은 주지 않는다(결과를 돌려받는 일회성 위임). 매 회차 새로 띄우고,
이전 회차 내용은 아래 표에 적은 것만 넘긴다. 사안이 코드라면 `subagent_type: "general-purpose"` 로
읽기 도구를 쓰게 한다.

| 역할 | model | 받는 것 | 내는 것 |
|---|---|---|---|
| 비판 | opus | 사안 브리프, 직전 회차 종합 | 번호 붙인 비판 목록 |
| 옹호 | opus | 사안 브리프, 이번 회차 비판, 직전 회차 종합 | 비판 번호별 재반론 |
| 종합 | opus | 사안 브리프, 이번 회차 비판·재반론, 직전 회차 종합 | 쟁점별 판정과 결론 |

1회차의 "직전 회차 종합"은 없음이다.

**model 은 셋 다 opus 가 기본이다.** 바꾸는 경우는 둘뿐이다.

- 사용자가 역할별 모델을 지정하면 그대로 따른다(예: "비판은 sonnet 으로").
- 같은 메시지에 `/fable-advisor` 가 함께 있으면 **종합만** `model: "fable"` 로 띄우고, 비판·옹호는
  opus 로 둔다. 이때 fable-advisor 스킬의 자문 절차는 따로 돌리지 않는다. fable 종합이 곧 그 자문이다.
  종합은 다음 단계의 입력이므로 fable-advisor 처럼 비동기로 두지 않고 끝날 때까지 기다린다.

### 비판 프롬프트 요지

- 사안의 가장 약한 곳을 찾는 적대적 검토자다. 칭찬과 총평은 쓰지 않는다.
- 비판 한 건은 **주장·근거·그것이 맞을 때의 결과**를 갖는다. 근거를 못 대는 의심은 쓰지 않는다.
- 심각도(치명/중대/경미) 순으로 3\~7건. 사소한 표현 지적으로 수를 채우지 않는다.
- 2회차 이후: 직전 종합이 **해소됨**으로 판정한 쟁점은 새 근거가 없으면 다시 꺼내지 않는다. 미해결
  쟁점을 더 파거나, 아직 아무도 보지 않은 각도를 찾는다.

### 옹호 프롬프트 요지

- 사안을 지지하는 쪽이다. 비판 번호마다 **반박 / 부분 인정 / 인정** 중 하나를 고르고 근거를 단다.
- 맞는 비판은 인정하고, 인정한 것은 사안을 어떻게 고치면 살아나는지 제시한다. 이기려고 틀린 반박을
  하지 않는다 — 억지 반박은 종합에서 그대로 감점된다.
- 비판이 놓친 사안의 강점이 있으면 마지막에 짧게 덧붙인다.

### 종합 프롬프트 요지

- 중립 판정자다. 어느 쪽 편도 들지 않고, 기계적으로 반반 나누지도 않는다.
- 쟁점(비판 번호)마다 **비판 우세 / 옹호 우세 / 미해결** 과 그 이유를 한 줄로 적는다. 직전 종합의
  판정을 이번 논의가 뒤집었으면 그렇게 적는다.
- 결론: 사안을 그대로 가도 되는가, 고쳐서 가야 하는가, 접어야 하는가. 고친다면 무엇을 먼저.
- 다음 회차가 있으면 **미해결 쟁점 목록**을 따로 적는다. 다음 비판이 이것을 받는다.

## 2. 조기 종료 (n ≥ 3 일 때만)

n 이 3 이상이면 **2회차부터** 세 역할 모두 출력 마지막 줄에 아래 중 하나를 쓰게 한다.

```
PROGRESS: continue
PROGRESS: stalled — <한 줄 이유>
```

`stalled` 는 "이 회차에서 새 쟁점도, 기존 판정을 바꿀 근거도 나오지 않았다"는 뜻이다. 프롬프트에
그 기준을 적고, 아직 미해결 쟁점이 파고들 여지가 있으면 `continue` 라고 못박는다.

- **비판**이 `stalled` → 옹호를 건너뛰고 바로 그 회차 종합을 **최종 종합**으로 띄운다.
- **옹호**가 `stalled` → 그 회차 종합을 최종 종합으로 띄운다.
- **종합**이 `stalled` → 그 종합이 최종 결론이다. 남은 회차를 돌리지 않는다.

최종 종합으로 띄울 때는 프롬프트에 "이것이 마지막 회차다, 미해결 쟁점 목록 대신 남은 쟁점을 결론에
반영하라"를 넣고 누가 왜 멈췄는지 전달한다. 비판이 멈춘 경우라면 그 회차 비판 목록 대신 직전 종합과
멈춘 이유를 넘긴다.

다음은 하지 않는다.

- 1회차에는 PROGRESS 줄을 요구하지 않는다. 1회차는 항상 끝까지 돈다.
- n 이 1\~2 면 PROGRESS 줄을 요구하지 않고 지정 횟수를 그대로 돈다.
- 리더가 "별 진전이 없어 보인다"며 임의로 끊지 않는다. 종료는 서브에이전트의 `stalled` 와 n 소진뿐이다.
- 줄이 없거나 형식이 틀리면 `continue` 로 읽는다.

## 3. 진행

회차 안의 세 호출은 앞 출력이 뒤 입력이라 **순차**로 띄운다. 회차 사이에는 묻지 않는다.
매 회차가 끝나면 사용자에게 한 줄로 알린다: `2/3회차 끝 — 비판 5건 중 옹호 우세 2, 미해결 2`.

## 4. 보고

끝나면 다음을 낸다.

1. **최종 결론**: 마지막 종합의 결론을 맨 앞에. 내 말로 바꾸지 않고, 길면 요점만 추리되 판정을 바꾸지 않는다.
2. **쟁점 표**: 쟁점별 최종 판정(비판 우세/옹호 우세/미해결)과, 회차를 거치며 판정이 바뀐 것.
3. **진행 기록**: 돈 회차 수 / 지정 n, 종료 사유(n 소진 / 몇 회차에 누가 `stalled`, 그 이유).
4. 내 의견이 종합과 다르면 **따로 라벨을 붙여** 한두 줄로만 덧붙인다. 종합 결론에 섞지 않는다.

세 역할의 원문 전체는 보고에 붙이지 않는다. 사용자가 원하면 그때 회차별로 보여준다.
