# Follow-through — 사용자가 다음에 칠 한 줄을 먼저 친다

Claude Code 는 턴이 끝날 때마다 별도 요청으로 "이 결과를 본 사용자가 다음에 칠 프롬프트" 를 하나
예측해 입력창에 회색으로 띄운다(→·Tab 으로 수락). 그 제안은 화면에만 있고 대화 기록·hook 어디에도
남지 않으므로 이 스킬이 읽어 올 수 없다. 대신 **같은 예측을 직접 여러 개** 만들고, 사용자가 수락했을
법한 것을 대신 실행한다.

판단의 축은 하나다: **이 결과를 본 사용자는 다음에 뭐라고 칠까?** 사용자가 고개를 끄덕이며 → 를
눌렀을 것은 하고, 잠깐 멈춰 생각했을 것은 묻는다.

## 1. 결산

아래 소스를 **모두** 훑어 "끝나지 않은 것" 을 모은다. 인자가 있으면 그것을 먼저 반영한다.

- 대화: 하기로 했거나 "나중에" 로 미룬 것, 사용자가 지나가듯 언급하고 잊은 것, 내가 보고에서
  "남은 일" 로 적은 것.
- 작업 트리: `git status`·미커밋 변경·push 안 된 커밋·stash, 이번에 만든 임시 파일·디버그 출력.
- 검증: 바꾼 코드에 닿는 테스트·린트·타입 검사·빌드를 실제로 돌렸는가.
- 파급: 바꾼 동작을 설명하는 문서·README·설정 예시·스킬 본문, 같은 버그·패턴이 남은 다른 곳.
- 실행 중인 것: 백그라운드 태스크·띄워 둔 서버·서브에이전트.
- backlog 가 있으면: 이번 작업에 해당하는 태스크의 상태·notes.

완료 기준: 소스마다 "해당 없음" 또는 찾은 항목이 있다.

## 2. 예측

결산 결과를 보고, 사용자가 칠 법한 **다음 프롬프트를 짧은 명령문으로** 여러 개 쓴다(제안 기능처럼
"테스트도 돌려줘", "README 도 고쳐줘", "푸시해줘" 같은 한 줄). 각 줄을 셋 중 하나로 가른다.

- **한다** — 되돌릴 수 있고, 사용자가 요청한 목표·범위를 바꾸지 않는다. 예: 실패한 테스트 고치기,
  린트·타입 오류, 영향받은 문서 갱신, 내가 만든 임시물 정리, 같은 수정이 필요한 이웃 코드, 빠진 테스트,
  그 환경 규칙이 묻지 않고 하라는 커밋·push.
- **묻는다** — 목표·범위·접근을 바꾸는 것, 되돌리기 어려운 것(삭제·force push·마이그레이션), 밖으로
  나가는 것(메일·메시지·이슈/PR 코멘트·PR 생성·머지·배포·공개 게시), 비용이 큰 것(긴 실행·다수 에이전트).
  **환경 규칙이 "묻고 하라" 는 것은 사용자가 이 스킬로 위임했어도 묻는다.**
- **버린다** — 근거 없는 추측, 취향 차원의 리팩터링, 사용자가 이미 거절한 것.

완료 기준: 모든 후보가 세 갈래 중 하나에 들어가 있다.

## 3. 실행과 반복

**한다** 를 실행하고 각각을 검증한다(테스트 통과·명령 성공을 눈으로 확인). 실행 결과로 새 후보가
생기면(고친 김에 드러난 다른 실패 등) 2 로 돌아간다.

완료 기준: 직전 라운드가 **한다** 에 새 항목을 하나도 만들지 못했다. 같은 항목을 두 번 시도해 실패하면
**묻는다** 로 옮기고 멈춘다 — 헛돌지 않는다.

## 4. 보고

- 한 것: 항목별 한 줄 + 검증 결과(실패했으면 그대로).
- 묻는다: AskUserQuestion 으로 한 번에 묻고, 답에 따라 3 을 이어 간다. 밖으로 나가는 게시는 승인 직전에
  최종본을 보여 준다.
- 버린 것: 있으면 한 줄로만.
