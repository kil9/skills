# Cleanup Memory — 장기 기억 감사

**머신 로컬 지침(`~/.codex/AGENTS.local.md`)에 남길 것은 오래 변하지 않는 취향·관계·방침·규칙
뿐이다.** 함정·실측·조사 결과·"지금 이렇게 돼 있다"는 상태는 그 자산이 사는 repo 의
`backlog/docs/`(없으면 repo 관례의 문서)로 내리고 지침에서 지운다.

> **`$learn` 과 혼동 금지.** learn 은 이번 세션의 학습을 **추가**한다. 이 스킬은 이미 쌓인 것을
> **감사·이관·삭제**한다. 이관한 뒤 남길 문서를 다듬는 것은 `$zip-it` 기준을 따른다.

## 왜 이 작업이 필요한가

지침은 코드와 함께 갱신되지 않는다. repo doc 은 같은 커밋에서 고쳐지고 grep 되지만, 지침은 아무도
안 고쳐서 **오래된 '현재값'이 매 세션 답변 정확도를 갉아먹는다.** 2026-08-22 첫 감사에서 항목
20건 중 17건이 함정·조사 로그였고, 저장소 이관 뒤 죽은 경로를 가리키거나 "현재 사용 중인 펌웨어"가
패치 두 개 전 것으로 남아 있었다.

## 절차

### 1. 전수 수집

머신 로컬 지침과, 그것이 참조하는 문서를 모두 읽는다. 항목 수와 총 바이트를 센다.

**완료 기준**: 감사 대상 전부를 읽었다.

### 2. 사실 대조 — 읽은 것을 믿지 말고 실측한다

본문이 가리키는 것을 현재 상태와 대조한다. 이 단계가 감사의 값을 만든다.

- **경로**: 적혀 있는 파일·스크립트가 아직 존재하는가. 저장소 이관·리팩터링으로 통째로 죽어 있는
  경우가 많다.
- **현재값**: "현재 사용 중", "조치 현황", 버전·바이너리명·수치. 낡았는지 싸게 검증되면 확인하고,
  비싸면 그 주장을 이관 대상에서 빼거나 "그때 확인하라"로 바꿀 후보로 표시한다.
- **커버리지**: 그 지식을 **이미 담은 doc 이 있는지 repo 에서 grep 한다.** 있으면 이관이 아니라
  그냥 삭제다. 새 doc 을 만들어 중복을 늘리지 말 것.

**완료 기준**: 항목 한 건마다 (경로 유효성 / 커버 하는 doc / 낡은 현재값) 세 항목의 판정이 있다.

### 3. 분류하고 승인받는다

네 갈래로 가르고, **실행 전에 사용자에게 제시한다**(이 게이트는 건너뛰지 않는다 — 삭제가 섞여 있다).

| 갈래 | 처리 |
|---|---|
| 영구 정책·취향·작업 규칙 | 지침에 유지 |
| 과거엔 맞지만 지금은 낡음 | 낡은 부분을 도려내고 이관 또는 삭제 |
| 살릴 가치가 있는 함정·실측 | repo doc 으로 이관 후 지침에서 삭제 |
| 이미 doc 이 커버 / 그때 찾으면 되는 값 | 그냥 삭제 |

판별이 헷갈리면: **버전·날짜·파일명·수치·현재 상태를 품고 있으면 지침이 아니라 doc 감이다.**

**완료 기준**: 사용자가 실행 범위를 승인했다.

### 4. 백업

지우기 전에 감사 대상을 작업용 임시 디렉터리에 복사하고 파일 수를 보고한다. 되돌릴 수 있어야
과감하게 정리할 수 있다.

**완료 기준**: 백업 경로와 파일 수를 사용자에게 알렸다.

### 5. 이관

대상 repo 의 체크아웃을 **먼저 동기화한다.** stale 한 곳에 새 doc 을 만들면 그 사이 원격에 생긴
doc 과 **ID 가 충돌한다**(실제로 38커밋 stale 이라 doc-29·30 을 모르고 31을 쓸 뻔했다).
`git rev-list --left-right --count` 로 확인하고, 파괴적 작업 전에는 `git cherry` 로 고유 커밋을 본다.

- 다루는 doc 이 이미 있으면 새로 만들지 말고 `## §N` 절을 덧붙인다. doc 끼리 `§N` 으로 서로 참조한다.
- **이관하면서 낡은 것을 버린다.** 경로는 현행으로 교정하고, **빌드마다 바뀌는 값(현재 펌웨어명,
  BIOS 버전, 조치 진행 상황)은 아예 적지 않고 "그때 확인하라"로 대체한다.** 그대로 옮기면 지침에서
  썩던 것이 doc 에서 썩을 뿐이다.
- 조사 로그는 결론으로 압축한다 — 시각별 서사·"관찰 중"·"다음 카드"는 값이 없다. 값은 지문·판별법·
  반박된 가설이다.
- doc 번호는 생성 후에야 확정되므로, **본문에 쓴 상호참조 번호를 마지막에 교정한다.**
- repo 의 AGENTS.md 에 doc 색인이 있으면 함께 갱신한다.

**완료 기준**: 새 doc 이 CLI/목록에 인식되고, 이관한 지식이 새 위치에 실제로 있으며(grep), 죽은
경로가 남아 있지 않다.

### 6. 지침 재구성

- 삭제 대상을 지운다.
- 남은 것은 정책만 담도록 다시 쓴다. 근거는 **관측된 실패 한 줄**로 줄이고 상세는 doc 에 맡긴다.
- 서두에 **"여기에는 정책만 둔다, 함정은 <repo>/backlog/docs 에 있다"** 를 박아 재발을 막는다.

**완료 기준**: 남은 것 전부가 정책이고, 전후 항목 수·바이트를 보고했다.

### 7. 커밋

이관으로 생긴 repo 변경을 `$commit` 규칙대로 커밋한다. 머신 로컬 지침은 git 이 아니므로 커밋
대상이 아니다. 여러 repo 를 건드렸으면 repo 마다 따로 커밋한다.
