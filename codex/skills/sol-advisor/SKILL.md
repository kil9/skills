# Sol Advisor

사용자가 `/sol-advisor` 또는 `$sol-advisor`를 직접 적었을 때만 Sol을 자문역으로 호출한다. 계획의
중요도나 난도만으로 이 스킬을 자동 호출하지 않는다.

## 1. 자문 대상과 모드 결정

자문 대상을 다음 순서로 정한다.

1. 호출과 같은 메시지에 있는 요청이나 초점을 사용한다.
2. 호출만 있으면 직전 대화의 가장 실질적인 요청·초안·계획을 사용한다.
3. 대상이 여전히 불명확하면 한 가지 짧은 질문으로 확정한다.

상황에 맞게 한 모드를 고른다.

- 검토·비평: 먼저 만든 답안·계획·diff의 허점과 대안을 검토한다. 기본 모드다.
- 선조언: 아직 방향을 정하지 않았거나 큰 되돌림 비용이 예상될 때 먼저 관점을 받는다.
- 병기: 정답이 하나가 아닌 판단에서 주 에이전트와 Sol 관점을 합치지 않고 나란히 제시한다.

## 2. 독립 자문 호출

`collaboration.spawn_agent`를 한 번 호출한다. 사용자가 여러 자문을 명시하지 않은 한 agent 하나만 쓴다.

- `agent_type`: `default`
- `model`: `gpt-5.6-sol`
- `reasoning_effort`: `high`
- `fork_turns`: `none`
- `task_name`: 작업을 나타내는 짧은 snake_case 이름

`fork_turns=none`이라 자문 agent는 대화를 상속하지 않는다. `message`에 다음을 자급자족하도록 넣는다.

- 사용자의 원래 목표와 제약
- 선택한 자문 모드와 원하는 초점
- 검토 모드면 현재 답안·계획·diff 전문
- 필요한 관련 파일의 절대 경로와 읽을 범위
- 바꾸면 안 되는 조건과 기대 출력

자문 agent에게 구현·파일 수정·외부 게시를 맡기지 않는다. 관련 파일을 읽고 조언만 반환하도록 한다.
호출 뒤 `collaboration.wait_agent`로 완료를 기다리고 최종 응답을 회수한다. 실패하면 모델 식별자와 API
오류를 그대로 요약하고, 다른 모델로 조용히 대체하지 않는다.

## 3. 비판적 반영과 전달

자문을 정답으로 취급하지 않는다. 근거를 원 요청·코드·문서와 대조해 다음처럼 처리한다.

- 타당한 지적은 답안이나 계획에 반영한다.
- 근거가 약하거나 제약과 충돌하는 제안은 제외하고 이유를 남긴다.
- 병기 모드는 `주 에이전트 관점`과 `Sol 관점`을 분리해 보여준다.

최종 응답에 Sol 자문을 사용했다는 사실, 반영한 핵심, 반영하지 않은 핵심과 이유를 짧게 밝힌다.
