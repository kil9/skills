# Zip It

에이전트가 읽는 문서의 정보 단가를 높인다. 짧게 만드는 것 자체가 목표가 아니며, 강도는 문서마다 적응적으로 정한다: 전부 삭제해도 되고, 압축이 전혀 안 돼도 되고, 빠져 있던 값진 지식이 있으면 오히려 길어져도 된다.

**정기 스케줄로 돌리지 않는다 — 조건으로 돌린다.** 압축할 것이 없을 때도 diff 가 나와 검토 부담만 남기 때문이다. 돌릴 조건: 한 작업 묶음이 여러 문서·스킬에 절을 대량 유입시킨 직후, 같은 문서를 읽을 때마다 "이 절이 왜 있지"가 반복될 때, 문서가 눈에 띄게 커졌다고 체감할 때.

## 판단 기준

실행 시점의 에이전트는 그때의 신선한 상황을 직접 탐색해 스스로 판단할 수 있다. 나중에도 쉽게 판단할 수 있는 내용을 미리 적어둘 필요는 없고, 탐색을 여러 번 하거나 실패를 몇 번 겪어야 알게 되는 지식은 적어두는 쪽이 싸다.

- **삭제**: 탐색 한두 번으로 파생되는 것. 디렉터리 트리와 파일별 한 줄 설명, Makefile 타깃이나 CLI --help 나 스크립트 usage 를 옮겨 적은 표, 워크플로 파일 목록, 모델이 이미 아는 일반 지식(표준 도구 사용법, 튜토리얼조 설명). 진실의 원본이 따로 있으면 한 줄 포인터로 치환한다.
- **보존하되 자리를 옮김**: 유통기한이 남은 실패 유래 지식. 외부 엔드포인트와 인증 방식의 함정, 디버깅 끝에 얻은 정확한 명령, 순서 제약, 한쪽을 바꾸면 다른 쪽도 고쳐야 하는 크로스 파일 결합, 조용히 실패하는 함정, 미설정 시 동작 같은 의미론. 이 지식은 압축을 이유로 버리지 않고, 문서에 빠져 있지만 대화나 이력에서 확인되면 새로 적는다. 다만 **적는 곳은 상시 로드 문서가 아니다** — 아래 절을 따른다.
- **삭제(실패 유래라도)**: 금방 낡을 지식. 진행 중인 마이그레이션의 중간 상태, 다음 릴리스·컷오버에 사라질 우회, 이미 지나간 이행 구간, 특정 버전·인스턴스에만 걸리는 버그, 곧 끝나는 작업의 진행 상황. 기준은 **그 지식이 참인 조건이 언제 사라지는지 보이는가** 다 — 보이면 다른 문서로 옮기지도 말고 지운다. 낡은 함정은 없는 것보다 나쁘다(읽는 사람이 그 우회를 실제로 적용하고, grep 이 그것을 현행으로 돌려준다). 애매하면 옮기되 **유효 조건과 관측 날짜를 한 줄로 함께 적어** 다음 압축이 판정할 수 있게 한다.
- **목표로 치환**: 열거·수치·순서로 굳은 기계적 규정. 같은 결과를 "무엇을 달성하라" 한 줄로 서술했을 때 실행 시점의 모델이 스스로 도달하면, 규정을 지우고 목표만 남긴다. 남길 근거는 하나뿐이다 — **관측된 실패**: 모델이 그 목표 아래서 틀린 방향으로 간 것을 실제로 본 규정만 유지하고, 그 관측을 한 줄로 함께 적는다.
- **무손실**: 행동 규칙(기본 동작 override), 승인 게이트, 안전/보안 규칙, 스킬 frontmatter 의 description(트리거 매칭에 쓰인다). 문구는 다듬어도 규칙의 의미는 잃지 않는다. 여기에 더해 사용자가 명시적으로 요구한 값(분량 하한 등)도 무손실이다 — 관측이 없다는 이유로 위의 '목표로 치환' 대상으로 오분류하지 않는다.
- **검증 후 정정**: 낡아 보이는 사실 서술은 현재 상태와 대조한다. 싸게 검증되면 고치고, 검증이 비싸면 주장을 빼거나 발견 사항으로 보고만 한다.

## 함정은 상시 로드 문서에 쌓지 않는다

AGENTS.md·CLAUDE.md 는 매 세션 자동 로드되므로 한 줄마다 상시 비용이 붙는다. 재현이 어렵거나 디버깅이 오래 걸린 함정일수록 서술이 길어지는데, 그것을 한 건씩 이 파일에 적으면 대부분의 세션이 쓰지도 않을 지식을 매번 사는 꼴이 된다. 함정 자체는 값지므로, **지우지 말고 내린다.**

- **내릴 곳**: backlog 가 있으면 backlog doc(`backlog doc create`), 없으면 별도 문서(`docs/`, `NOTES.md` 등 repo 관례를 따른다). 배관·주제별로 한 문서에 모으고, 로그 태그·에러 원문·명령을 **원문 그대로** 실어 grep 이 맞게 한다.
- **상시 문서에 남길 것**: "뭔가 이상하면 먼저 여기를 검색하라"는 안내 한 문단 — 검색 명령과 현행 문서 목록(문서당 한 줄, 다루는 범위만). 그 이상은 두지 않는다.
- **증상 색인·요약을 상시 문서에 두지 않는다.** 색인이 요약을 들고 있으면 문서와 이중관리가 되고, 그 자체가 다시 비대해진다. 색인으로 바로 짚는 능력을 잃는 것은 감수하는 트레이드오프다 — grep 이 대신한다.
- 실측(kil9conf, 2026-07-29): 함정 서술을 doc 으로 내리고 증상 색인까지 걷어내 AGENTS.md 가 277 → 68줄(-76%)이 됐다 — 이 정도 강도가 정상 범위다.
- 재발 방지: 그 문서 서두에 "새로 알아낸 것은 여기 늘리지 말고 해당 문서에 적는다" 한 줄을 남긴다.

## 절차

1. 대상 결정: 인자 경로가 있으면 그것. 없으면 cwd 의 AGENTS.md (CLAUDE.md 가 심링크면 원본 쪽을 수정). 스킬이 대상이면 SKILL.md 와 딸린 참조 파일까지 포함한다.
2. 대상 전체와, 대상이 중복 서술하는 진실의 원본들을 읽는다.
3. 청크 단위로 위 기준에 따라 분류하고 재작성한다.
   - 삭제 대상 위치에 있지만 실패 유래인 지식은 버리지 말고 제자리로 이전한다(backlog doc·별도 문서, 코드 주석, .env.example, 에이전트 메모리 등). 이전 전에 대상 문서에 그 내용이 이미 있는지 grep 으로 확인하고, 없으면 먼저 쓰고 나서 지운다. **유통기한이 짧은 것은 이전 대상이 아니다** — 그냥 지운다(위 '삭제(실패 유래라도)').
   - 같은 종류의 비대화가 재발할 문서면 "여기에 X 를 유지하지 않는다" 한 줄로 방지선을 친다.
4. 스킬이 대상이면 추가로: 모델이 이미 할 줄 아는 방법 설명은 지우고, 이 환경에서만 통하는 정확한 절차와 제약만 남긴다. 예시는 하나면 충분하다. 다른 도구용 미러나 사본이 있으면 압축된 원본 기준으로 함께 갱신한다.
5. 독립 동작해야 하는 문서(글로벌 규칙 없이도 동작해야 하는 AGENTS.md 등)는 행동 규칙 코어를 유지한다.
6. 검증: 남긴 사실 서술이 현재 상태와 맞는지, 무손실 대상이 빠지지 않았는지, 내린 지식이 새 위치에 실제로 있는지 전후 내용을 대조해 확인한다. 전면 재작성이었다면 항목 수를 이전 커밋과 대조한다 — 위 실측에서 이 대조가 누락 1건을 잡아 복구했다. (backlog CLI 에 `--notes` 로 코드 조각을 넘길 때 큰따옴표 안의 백틱은 셸 명령 치환으로 실행된다 — heredoc 파일에 쓰고 `"$(cat 파일)"` 로 넘긴다.)
7. 보고: 전/후 바이트, 삭제/유지/보강/정정 요약, 범위 밖 발견. 커밋은 사용자가 요청할 때만, 대상 repo 의 커밋 규칙대로 한다.
