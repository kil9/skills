# 레거시 모드 (§L)

[`../SKILL.md`](../SKILL.md) 의 §L 이다. repo 에 `backlog/` 가 없고 `PLAN.md`(또는 `PLAN_*.md`)만
있을 때만 편다 — backlog 모드 실행은 이 파일에 도달하지 않는다.

## L. 레거시 모드 (PLAN.md)

대상은 `PLAN.md`, 없으면 가장 최근 수정된 `PLAN_*.md`(어느 파일을 쓰는지 알린다). 전체를 읽고 미완료 항목·우선순위·의존·완료 조건을 파악한다.

호출 인자 분기는 §1 과 동일하다: 번호 지정(T-N)이면 그 태스크만 지정 순서대로, 작업 서술이면 PLAN 에 T-N 태스크로 등록(완료 조건 포함)한 뒤 바로 진행, 인자 없으면 아래 규칙으로 고른다. `m-N`/`M-N` 마일스톤 지정은 backlog 모드 전용이며, 레거시 PLAN에서는 지원하지 않는다.

- **아이디어(I-N) 제외**: "아이디어 (보류)" 섹션 항목은 진행 대상이 아니다. 태스크(T-N)만 순서대로 처리한다(M-N 은 태스크를 묶는 상위 단위일 뿐 실행 단위가 아니다). 사용자가 특정 아이디어 착수를 지시하면 상세 인터뷰를 거쳐 정식 태스크로 편입한 뒤 진행한다.
- **상태 표기** `[ ]` TODO / `[→]` IN_PROGRESS / `[x]` DONE / `[!]` BLOCKED: `[→]` 가 있으면 최우선으로 속행, `[ ]` 는 순서·우선순위·의존에 따라, `[!]` 는 건너뛰되 사유가 해소됐으면 `[ ]` 로 되돌려 포함, `[x]` 는 제외.

루프(태스크당 구현 → 검증 → 커밋):

1. **준비**: 범위·완료 조건 정의, 관련 파일 읽기. 판단이 필요한 사항은 `request_user_input` 으로 사전 해소. 착수 직전 상태를 `[→]` 로 갱신.
2. **구현**: 작고 안전한 변경. 새 코드엔 테스트, 버그 수정은 회귀 테스트 먼저. 안전하지 않은 우회 금지.
3. **검증**: 테스트 전부 통과 + 빌드 성공 + 완료 조건 동작 확인(성공·실패·경계). 통과해야 커밋으로 간다. 사람 개입 없이는 불가하면 `[!]` + 사유 한 줄로 표시하고 다음 태스크로.
4. **커밋**: 검증 직후 `$commit` 규칙으로 즉시. 커밋 전 PLAN 항목을 `[x]` 로 갱신해 같은 커밋에 포함.

중요한 설계 결정은 PLAN.md 에 다음 형식으로 기록한다:

```markdown
### 디자인 결정: [제목]
- **날짜**: YYYY-MM-DD
- **결정**: 선택한 방향
- **이유**: 근거(트레이드오프 포함)
- **대안**: 검토한 다른 방법
```

**세션 위생**: PLAN 은 세션 리셋 후에도 재개 가능한 진실원본이다. 커밋 직후 경계에서 세션을 리셋하고 재진입해도 손실이 없다.

완료 보고: 완료 항목, `[!]` 로 남긴 태스크와 사유, 설계 결정, 추가 확인이 필요한 사항을 요약해 알린다.
